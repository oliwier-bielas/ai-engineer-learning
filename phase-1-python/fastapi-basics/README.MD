# FastAPI Basics – Tasks API
 
Second exercise of **Phase 1 (Python)** of my AI Engineer learning path.
A small REST API for a to-do list, built with FastAPI and Pydantic. Data is kept in memory.
 
## Task
 
Build a CRUD API for tasks:
 
- a task has `id` (assigned by the server), `title` (required, not empty) and `done` (defaults to `false`)
- tasks are stored in memory in a service and are reset when the server restarts
- the router contains no business logic, it only calls the service
- separate models for input (only `title`) and output (`id`, `title`, `done`), so the client cannot set `id` or `done`
- correct HTTP status codes, including 404 for missing tasks and 422 for invalid input
- every endpoint tested in the interactive docs at `/docs`
## Endpoints
 
| Method | Path | Description | Status |
| --- | --- | --- | --- |
| `GET` | `/tasks` | list all tasks | 200 |
| `GET` | `/tasks/{task_id}` | get one task | 200 / 404 |
| `POST` | `/tasks` | create a task, body: `{"title": "..."}` | 201 / 422 |
| `PATCH` | `/tasks/{task_id}/done` | mark a task as done | 200 / 404 |
| `DELETE` | `/tasks/{task_id}` | delete a task | 204 / 404 |
 
### Example responses
 
```json
// GET /tasks
[
  {"id": 1, "title": "Buy milk", "done": true},
  {"id": 2, "title": "Go to barber", "done": false}
]
 
// GET /tasks/99 → 404
{"detail": "Task 99 not found"}
 
// POST /tasks with {"title": "Write unit tests"} → 201
{"id": 5, "title": "Write unit tests", "done": false}
 
// POST /tasks with {"title": ""} → 422 (validation error generated by FastAPI)
 
// PATCH /tasks/2/done → 200
{"id": 2, "title": "Go to barber", "done": true}
 
// DELETE /tasks/2 → 204, empty body
```
 
## Learning goals
 
| Topic | What I practised |
| --- | --- |
| FastAPI basics | `FastAPI()`, route decorators, running with `fastapi dev` |
| Project structure | feature-based modules (`tasks/`) with `router`, `schemas` and `service`, `__init__.py` packages |
| Routing | `APIRouter` with `prefix` and `tags`, `include_router` |
| Path parameters | typed path parameters like `task_id: int` |
| Request body | Pydantic models as input, automatic validation |
| Validation | `Field(min_length=1, max_length=100)`, 422 responses |
| Response models | return type annotations controlling the response shape |
| Status codes | `status_code=` in the decorator, `fastapi.status` constants, 201 and 204 |
| Errors | `HTTPException` for 404 |
| Service layer | in-memory storage, a single service instance shared by the app, returning a copy of internal data |
| Python | `next()` with a generator as an equivalent of JS `find`, model inheritance in Pydantic |
 
### Coming from NestJS
 
| NestJS | FastAPI |
| --- | --- |
| controller | `APIRouter` in `router.py` |
| DTO + `class-validator` | Pydantic model in `schemas.py` |
| `@Param()`, `@Query()`, `@Body()` | inferred from type hints and argument names |
| `throw new NotFoundException()` | `raise HTTPException(status_code=404)` |
| injectable service | module-level service instance |
 
## Project structure
 
```

├── app/
│   ├── __init__.py

│   └── tasks/
│       ├── __init__.py
```

## How to run
 
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
 
fastapi dev app/main.py
```
 
- API: http://127.0.0.1:8000
- Interactive docs: http://127.0.0.1:8000/docs
## Known simplifications
 
- Data lives in memory, so there is no database yet.
- The service raises `HTTPException` directly. In a bigger app the service would raise domain exceptions (e.g. `TaskNotFoundError`) and an exception handler would map them to HTTP responses, so the service stays independent of HTTP. That is planned for the next project.
